== Überblick

Professionelles CV-Management-System mit AsciiDoc, optimiert für Consultants.

**Features:**

* 📄 **Mehrsprachig**: Deutsch & Englisch
* 🏢 **Company Branding**: Wechsel zwischen Auftraggebern per Attribut
* 📅 **Automatisches Datum**: Lokal aktuell, CI commit-basiert
* 🚀 **GitHub Actions**: Automatische Builds & Releases
* 🐳 **Docker-basiert**: Konsistente Build-Umgebung
* 📦 **Flexible Ausgabe**: Individual-PDFs + ZIP in Releases

== Schnellstart

=== Installation

**Voraussetzung**: https://taskfile.dev[Task] installieren

[source,bash]
----
# macOS
brew install go-task/tap/go-task

# Linux
sh -c "$(curl --location https://taskfile.dev/install.sh)" -- -d -b ~/.local/bin
----

=== CVs bauen

[source,bash]
----
task build
----

Generiert 4 PDFs im `output/` Verzeichnis:

* `CV_Tobias_Breitwieser_Vollversion_DE.pdf` - Vollständig (DE)
* `CV_Tobias_Breitwieser_Kurzversion_DE.pdf` - Kompakt (DE)
* `CV_Tobias_Breitwieser_Full_EN.pdf` - Full (EN)
* `CV_Tobias_Breitwieser_Short_EN.pdf` - Short (EN)

=== Release erstellen

[source,bash]
----
# Automatischer Tag (v2025.11.20)
task release

# Custom Tag
TAG=v1.2.3 task release

# Mehrere Releases am selben Tag: v2025.11.20, v2025.11.20-1, v2025.11.20-2
----

GitHub Action erstellt automatisch Release mit Individual-PDFs + ZIP.

== Features im Detail

=== Mehrsprachigkeit

Vollständig getrennte Inhalte für Deutsch und Englisch:

----
sections/
├── de/              # Deutsche Sections
│   ├── profile.adoc
│   ├── skills.adoc
│   ├── projects-current.adoc
│   └── ...
└── en/              # English Sections
    ├── profile.adoc
    ├── skills.adoc
    ├── projects-current.adoc
    └── ...
----

=== Company Branding

Ideal für Consultants - wechsle zwischen Auftraggebern:

**In `attributes.adoc` oder `attributes-en.adoc`:**
[source,asciidoc]
----
:company-branding: jernoxit  # jernoxIT Logo + Tagline
:company-branding: none      # Kein Branding
:company-branding: client-a  # Custom Branding
----

**Neues Branding erstellen:**
[source,bash]
----
cp sections/company/example-company.adoc sections/company/acme-corp.adoc
# Logo anpassen, Tagline ändern
----

**Verfügbare Brandings:**

* `jernoxit.adoc` - jernoxIT (Standard)
* `none.adoc` - Kein Branding
* `example-company.adoc` - Template

=== Automatisches Datum

Das `last-updated` Datum wird automatisch gesetzt:

* **Lokal**: Aktuelles Datum (`20.11.2025` / `November 20, 2025`)
* **GitHub Actions**: Commit-Datum (reproduzierbar)
* **Sprachspezifisch**: Deutsch `dd.mm.yyyy`, English `Month dd, yyyy`

=== GitHub Actions

**Automatischer Build bei:**

* Push auf `main` branch
* Pull Requests
* Git Tags (`v*`)
* Manuell über GitHub UI

**Docker-basiert:**

* Nutzt `asciidoctor/docker-asciidoctor` Container
* Schnell & konsistent
* Keine manuelle Dependency-Installation

**Artifacts:**

* Workflow-Runs: 4 separate PDF-Downloads (90 Tage)
* Releases: 4 Individual-PDFs + ZIP mit allen Versionen

== Häufige Aufgaben

=== 1. Variablen ändern

**Datei**: `attributes.adoc` (Deutsch) oder `attributes-en.adoc` (Englisch)

[source,asciidoc]
----
:hourly-rate: 130,0 EUR
:availability-date: 01.03.2026
:availability-percent: 90%
----

=== 2. Neues Projekt hinzufügen

**Wichtig**: In beiden Sprachen hinzufügen!

* Deutsch: `sections/de/projects-current.adoc`
* Englisch: `sections/en/projects-current.adoc`

[source,asciidoc]
----
=== MM/YYYY - MM/YYYY | Projekttitel

*Rolle:* Ihre Rolle +
*Kunde:* Kundenname

Projektbeschreibung hier...

*Technologien:* Tech1, Tech2, Tech3

'''
----

=== 3. Company Branding wechseln

**Dauerhaft** in `attributes.adoc`:
[source,asciidoc]
----
:company-branding: client-name
----

**Einmalig** beim Build:
[source,bash]
----
asciidoctor-pdf -a company-branding=client-name cv-main.adoc -o output/cv.pdf
----

=== 4. Projekt archivieren

. Projekt aus `sections/de/projects-current.adoc` & `sections/en/projects-current.adoc` ausschneiden
. Als Tabellenzeile in `projects-archive.adoc` einfügen:

[source,asciidoc]
----
|2025
|Projekttitel
|Kunde/Rolle
|Technologien
----

== Dateistruktur

[source]
----
cv-system/
├── Taskfile.yml              # Task-Definitionen
├── build.sh                  # Build-Script (via Docker unterstützt)
├── cv-main.adoc              # Haupt-CV (Deutsch)
├── cv-main-en.adoc           # Haupt-CV (Englisch)
├── attributes.adoc           # Variablen (Deutsch)
├── attributes-en.adoc        # Variablen (Englisch)
├── sections/
│   ├── de/                  # Deutsche Inhalte
│   ├── en/                  # English Content
│   └── company/             # Company Brandings
├── themes/                   # PDF Themes
├── .github/workflows/        # GitHub Actions
└── output/                   # Generierte PDFs
----

== GitHub Actions Details

=== Workflow-Artifacts

Nach jedem Build auf `main` oder bei PRs:

. Gehe zu https://github.com/tarfu/cv/actions
. Wähle Workflow-Run
. Download individual PDFs unter "Artifacts"

=== Releases erstellen

[source,bash]
----
task release
----

Erstellt automatisch:

* Git Tag (z.B. `v2025.11.20`)
* GitHub Release mit Beschreibung
* 4 Individual-PDFs als separate Downloads
* 1 ZIP-Datei mit allen PDFs (`CV_All_Versions_v2025.11.20.zip`)

View: https://github.com/tarfu/cv/releases

=== Manueller Workflow-Trigger

. https://github.com/tarfu/cv/actions/workflows/build-cv.yml
. "Run workflow" → Branch wählen → "Run workflow"

== Lokale Builds

=== Mit Task (empfohlen)

[source,bash]
----
task build
----

=== Mit build.sh direkt

[source,bash]
----
./build.sh
----

=== Mit Docker (wie CI)

[source,bash]
----
docker run --rm \
  -v $(pwd):/documents \
  asciidoctor/docker-asciidoctor \
  /bin/bash -c "cd /documents && ./build.sh"
----

=== Manuelle einzelne Builds

[source,bash]
----
# Deutsch Vollversion
asciidoctor-pdf -a pdf-theme=jernoxit -a full-version cv-main.adoc -o output/cv_de.pdf

# Englisch Kurzversion
asciidoctor-pdf -a pdf-theme=jernoxit cv-main-en.adoc -o output/cv_en.pdf

# Mit anderem Branding
asciidoctor-pdf -a company-branding=client-name cv-main.adoc -o output/cv.pdf
----

== Verfügbare Tasks

[source,bash]
----
task build       # Build all CV PDFs
task release     # Create and push git tag for release
task clean       # Clean output directory
task list        # List all available tasks
----

== Best Practices

**DO:**

* ✓ Beide Sprachen pflegen (DE & EN)
* ✓ `task build` vor Commits ausführen
* ✓ `task release` für Versionierung nutzen
* ✓ Company Branding per Attribut wechseln
* ✓ Git für Versionsverwaltung nutzen

**DON'T:**

* ✗ Datum manuell in attributes.adoc ändern (wird automatisch gesetzt)
* ✗ PDFs committen (werden automatisch gebaut)
* ✗ `cv-main.adoc` für Inhalte ändern (nur Struktur)
