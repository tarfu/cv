== Überblick

Dieses System verwaltet den Lebenslauf von Tobias Breitwieser mit AsciiDoc. Die Daten sind von der Gestaltung getrennt, sodass verschiedene PDF-Versionen aus den gleichen Quelldaten erzeugt werden können.

Die CVs sind in **Deutsch** und **Englisch** verfügbar und werden automatisch bei jedem Push auf den main Branch über GitHub Actions gebaut.

== Schnellstart

=== PDF generieren

[source,bash]
----
cd cv-system
./build.sh
----

Die PDFs finden Sie dann im `output/` Verzeichnis:

**Deutsche Versionen:**

* `CV_Tobias_Breitwieser_Vollversion_DE.pdf` - Vollständiger CV im jernoxIT-Design
* `CV_Tobias_Breitwieser_Kurzversion_DE.pdf` - Ohne ältere Projekte
* `CV_Tobias_Breitwieser_Minimal_DE.pdf` - Minimalistisches Design

**Englische Versionen:**

* `CV_Tobias_Breitwieser_Full_EN.pdf` - Full CV with jernoxIT design
* `CV_Tobias_Breitwieser_Short_EN.pdf` - Without archive projects
* `CV_Tobias_Breitwieser_Minimal_EN.pdf` - Minimal design

== Häufige Aufgaben

=== 1. Variablen ändern (Rate, Datum, etc.)

Datei: `attributes.adoc`

Beispiele:

[source,asciidoc]
----
:hourly-rate: 130,0 EUR          // Stundensatz anpassen
:availability-date: 15.02.2026   // Verfügbarkeitsdatum ändern
:availability-percent: 90%       // Verfügbarkeit in Prozent
----

Nach dem Ändern: `./build.sh` ausführen

=== 2. Neues Projekt hinzufügen

**Wichtig**: Projekt in beiden Sprachen hinzufügen!

* Deutsch: `sections/de/projects-current.adoc`
* Englisch: `sections/en/projects-current.adoc`

Template für ein neues Projekt:

[source,asciidoc]
----
=== MM/YYYY - MM/YYYY | Projekttitel

*Rolle:* Ihre Rolle +
*Kunde:* Kundenname

Beschreibung des Projekts. Was wurde gemacht, was war das Ziel,
welche Herausforderungen gab es?

*Aufgaben:* (optional)

* Aufzählung von Haupttätigkeiten
* Weitere wichtige Aufgaben
* Besondere Achievements

*Technologien:* Tech1, Tech2, Tech3, Tech4

'''
----

[TIP]
====
`'''` erzeugt eine horizontale Trennlinie zwischen Projekten.
====

=== 3. Projekt ins Archiv verschieben

**Wichtig**: In beiden Sprachen durchführen!

. Projekt aus `sections/de/projects-current.adoc` und `sections/en/projects-current.adoc` ausschneiden
. In `sections/de/projects-archive.adoc` und `sections/en/projects-archive.adoc` als Tabellenzeile einfügen:

[source,asciidoc]
----
|2025
|Projekttitel (kurz)
|Kunde/Rolle
|Technologien (kurz)
----

=== 4. Kompetenzen aktualisieren

**Wichtig**: In beiden Sprachen aktualisieren!

* Deutsch: `sections/de/skills.adoc`
* Englisch: `sections/en/skills.adoc`

Format:

[source,asciidoc]
----
**Kategorie**:: Wert1, Wert2, Wert3
----

Beispiel:

[source,asciidoc]
----
**Programmiersprachen**:: Go, Rust, Java, Kotlin, Python, TypeScript
----

== AsciiDoc Cheatsheet

=== Grundlegende Formatierung

[cols="2,3,3"]
|===
|Element |AsciiDoc |Ergebnis

|Fett
|`\*fett*`
|*fett*

|Kursiv
|`\_kursiv_`
|_kursiv_

|Code
|`\`code``
|`code`

|Zeilenumbruch
|` +` am Zeilenende
|Neue Zeile

|Horizontale Linie
|`'''`
|---

|===

=== Überschriften

[source,asciidoc]
----
= Titel (Level 0)
== Überschrift Level 1
=== Überschrift Level 2
==== Überschrift Level 3
----

=== Listen

[source,asciidoc]
----
// Normale Liste
* Punkt 1
* Punkt 2
** Unterpunkt
* Punkt 3

// Nummerierte Liste
. Erster
. Zweiter
. Dritter

// Definition Liste
Begriff:: Definition des Begriffs
Anderer Begriff:: Andere Definition
----

=== Tabellen

[source,asciidoc]
----
[cols="1,3,2"]
|===
|Spalte 1 |Spalte 2 |Spalte 3

|Wert A
|Wert B
|Wert C

|Wert D
|Wert E
|Wert F
|===
----

Mit Header:

[source,asciidoc]
----
[cols="1,3,2",options="header"]
|===
|Header 1 |Header 2 |Header 3

|Daten
|Mehr Daten
|Noch mehr
|===
----

=== Admonitions (Hinweise)

[source,asciidoc]
----
[NOTE]
====
Dies ist ein Hinweis.
====

[TIP]
====
Dies ist ein Tipp.
====

[IMPORTANT]
====
Dies ist wichtig.
====

[WARNING]
====
Dies ist eine Warnung.
====
----

=== Links und Fußnoten

[source,asciidoc]
----

// Fußnote

// Nummerierte Fußnote

^1^ Dies ist die Erklärung
----

== GitHub Actions - Automatischer Build

Das Repository nutzt GitHub Actions für automatisches Bauen der CV-PDFs. Der Workflow wird ausgelöst bei:

* **Push auf main Branch**: Automatischer Build bei jeder Änderung
* **Pull Requests**: Build-Preview für PRs
* **Tags** (z.B. `v1.0.0`): Automatisches Release mit PDF-Assets
* **Manueller Trigger**: Über GitHub UI → Actions → "Build CV PDFs" → "Run workflow"

=== PDFs herunterladen

**Workflow-Artefakte** (nach Push/PR):

. Gehen Sie zu: https://github.com/tarfu/cv/actions
. Klicken Sie auf den letzten erfolgreichen Workflow-Run
. Unter "Artifacts" finden Sie `cv-pdfs` zum Download
. Artefakte werden 90 Tage gespeichert

**Release-Assets** (bei Tags):

. Gehen Sie zu: https://github.com/tarfu/cv/releases
. Wählen Sie das gewünschte Release (z.B. `v1.2.0`)
. Alle 6 PDFs sind direkt downloadbar

=== Release erstellen

Um ein neues Release mit PDFs zu erstellen:

[source,bash]
----
# Tag erstellen und pushen
git tag v1.2.0
git push origin v1.2.0
----

Die GitHub Action erstellt automatisch ein Release mit allen PDFs.

=== Manuellen Build starten

. Gehen Sie zu: https://github.com/tarfu/cv/actions/workflows/build-cv.yml
. Klicken Sie auf "Run workflow"
. Wählen Sie den Branch
. Klicken Sie auf "Run workflow"

Die PDFs sind nach ~2 Minuten als Artefakt verfügbar.

== Erweiterte Nutzung

=== Verschiedene Versionen generieren

**Deutsche Versionen:**

Nur jernoxIT Vollversion:
[source,bash]
----
asciidoctor-pdf -a pdf-theme=jernoxit -a full-version \
  cv-main.adoc -o output/vollversion_de.pdf
----

Nur jernoxIT Kurzversion:
[source,bash]
----
asciidoctor-pdf -a pdf-theme=jernoxit \
  cv-main.adoc -o output/kurzversion_de.pdf
----

**Englische Versionen:**

Nur jernoxIT Full Version:
[source,bash]
----
asciidoctor-pdf -a pdf-theme=jernoxit -a full-version \
  cv-main-en.adoc -o output/full_en.pdf
----

Nur jernoxIT Short Version:
[source,bash]
----
asciidoctor-pdf -a pdf-theme=jernoxit \
  cv-main-en.adoc -o output/short_en.pdf
----

**HTML Versionen** (für Website):
[source,bash]
----
# Deutsch
asciidoctor cv-main.adoc -o output/cv_de.html

# Englisch
asciidoctor cv-main-en.adoc -o output/cv_en.html
----

=== Bedingte Inhalte

In den Section-Dateien können Sie bedingte Inhalte nutzen:

[source,asciidoc]
----
ifdef::detailed[]
Dies erscheint nur bei detaillierter Version
endif::[]

ifndef::detailed[]
Dies erscheint nur bei Kurzversion
endif::[]
----

Dann beim Build:
[source,bash]
----
asciidoctor-pdf -a detailed cv-main.adoc -o output/detailed.pdf
----

== Tipps für die Pflege

=== DO's ✓

* **Regelmäßig committen**: Nutzen Sie Git für Versionsverwaltung
* **Klein halten**: Kurze, prägnante Beschreibungen
* **Konsistent formatieren**: Gleiche Struktur bei allen Projekten
* **Variablen nutzen**: Datum, Rate etc. in `attributes.adoc` und `attributes-en.adoc`
* **Beide Sprachen pflegen**: Änderungen immer in DE und EN durchführen
* **Testen**: Nach Änderungen immer `./build.sh` ausführen
* **GitHub Actions nutzen**: Automatischer Build bei Push auf main

=== DON'Ts ✗

* **Keine manuellen Zeilenumbrüche**: AsciiDoc macht das automatisch
* **Keine HTML-Tags**: Nutzen Sie AsciiDoc-Syntax
* **Kein Copy-Paste aus Word**: Formatierung kann kaputt gehen
* **Nicht cv-main.adoc ändern**: Nur für Struktur-Änderungen

== Troubleshooting

=== PDF wird nicht generiert

Prüfen Sie:

. Ist asciidoctor-pdf installiert?
+
[source,bash]
----
gem install asciidoctor-pdf
----

. Gibt es Syntax-Fehler?
+
[source,bash]
----
asciidoctor-pdf cv-main.adoc
----
+
Fehler werden angezeigt

. Alle Dateien vorhanden?
+
Prüfen Sie ob alle `include::` Dateien existieren

=== Formatierung sieht komisch aus

* Prüfen Sie Tabellen-Syntax (oft Fehlerquelle)
* Kontrollieren Sie ob Admonition-Blöcke geschlossen sind (`====`)
* Achten Sie auf korrekte Anzahl von `=` bei Überschriften

=== Theme wird nicht angewendet

[source,bash]
----
# Prüfen Sie den Theme-Pfad
asciidoctor-pdf -a pdf-theme=jernoxit -a pdf-themesdir=themes cv-main.adoc
----
